# BUG 索引

## 活跃缺陷

- **BUG-031 观雅集安装审查的信任边界仍在渲染层**（P1，未修）。`ipc-guanji.ts:15` 把 `{ slug, name, description, caps, auth }` 与 `authorized` 一并从渲染层收进来，`capabilityReview` 只按 `caps` 推导风险（2026-10-01 第七轮）。能伪造 `auth=0` 的调用方同样能发 `caps: []`，或直接 `authorized=true`。正解：`installSkill` 只收 slug，caps 由主进程向 `/api/skills/<slug>` 取回后按同一 `LOW_RISK_CAPS` 推导，取不到按高危 fail-closed。证据与讨论见 [代码审阅（2026-10-01）](../40-质量/代码审阅-2026-10-01.md) 第十轮
- **BUG-032 快照顺序把全量复制放到启动路径上**（P2，未修，等并行会话）。`snapshotData` 原先因 `fs.cpSync` 目标在源内而每次抛错，等于从未备份；修好复制之后，`checkForUpdates`（`boot-desktop` 启动约 8 秒无条件调用）会在主线程同步拷整个数据目录。正解：先探到更新再备份。`ipc-data-ops.ts` 正被另一会话修改，本轮不与其争同一文件
