# SPEC — 运行时替换

本页是执行契约。意图在 [PRD](../20-需求/运行时替换.md)。方案取舍在 [ADR 0004](../70-决策/0004-gui-两档.md) 和 [ADR 0005](../70-决策/0005-进程内嵌入与插件删除.md)。

- 状态：契约已定。T4 与 T5 均已验证。不另写不变量
- 日期：2026-09-30

## 必须做什么

桌面主进程停止装载 dsh，改为进程内组合锁定点的 `@step-harness/coding-agent`。权限策略只传 `bypass` 或 `autopilot`。危险命令确认由本 GUI 的 `confirm` 完成。

## 输入

| 输入 | 允许值 | 不允许 |
|---|---|---|
| 权限策略 | `bypass`、`autopilot` | `ask`、`read-only`、`default`、`full-trust`、`bypassPermissions` |
| 确认回调 | 本 GUI 提供的 `confirm` | `--non-interactive-approval allow`，或跳过 SDK 审批回调 |
| 运行时来源 | `stepfun-ai/Step-Code` 的修订，接缝仍在；随包兜底 `93ebc5be` | 随机目录，或 `step update` 的已安装程序 |
| 沙箱信号 | 不发送 | `sandbox.enabled`；不迁入 `sandboxPolicy` |

接缝是 `createStepExtensionInline`。不单独把 `createStepCode` 或 `createStepAgentSession` 当作已接好的运行时。

## 输出

- 工具裁决来自当前加载修订对应预设的 `decideStepToolCall`。本 GUI 不改该函数。见 [ADR 0008](../70-决策/0008-跟随-step-code-源仓库.md)。
- 危险命令到达本 GUI 确认。没有确认界面时不得改写成自动放行。
- 界面词只出现「默认模式」「完全信任」。机器标识仍是 `bypass`、`autopilot`。

## 状态变化

- `dsh-runtime` 不再装载。
- 九个 Cordis 插件和市场插件装载器删除，不迁移。
- 宿主服务 `sandboxPolicy`、`approval`、`agents` 停止。桌面桥移除，或显式返回不可用。
- 会话和模型凭据留在 Step 运行时自己的存储根。本 GUI 不另造会话格式。
- 旧的四域 JSON 不读入新核。

## 边界条件

- 导入该包之前，运行时必须满足 `engines.node >=22.19.0`。不满足时升壳的运行时，不得改用 `--sdk-stdio`。
- 证据点仍是 `b68a955766dffd5fe45e3e0e2ca075d2b297ee65`，直到按 [冲突裁决](../00-项目/冲突裁决.md) 前移。它属于 `ra1nzzz/orchdesk` 的历史，不随本仓库演进（[ADR 0007](../70-决策/0007-精简版归属.md)）。
- `--sdk-stdio` 的 `permissionMode`、`--mode rpc` 和 `--non-interactive-approval allow` 都不是这两档的控制面。
- 运行时若带回 `ask` 或 `read-only`，不得显示成默认模式或完全信任。下一次由本 GUI 发出的预设只能是 `bypass` 或 `autopilot`。

## 不变量

本清单是不变量的唯一全文。[质量页](../40-质量/不变量.md) 只指向这里。

1. 两档机器标识与上游 `bypass`、`autopilot` 一致，不改其裁决函数。
2. 界面只有两个权限档名称。宿主兼容词不能变成第三档。
3. 危险命令的产品文案不得写成「任何模式都弹窗」，除非锁定点的 `strict` 行为已改成确认。当前源码对 `strict` 是拒绝。
4. 无界面运行不得继承「未选择策略时交互默认 Bypass」。
5. 没有按删除清单改接之前，不改宿主代码。
6. 不把宿主兼容词、`--approval-mode auto` 或 `STEP_AUTOPILOT` 单独写成第三档。完全信任是 `autopilot` 预设，不是单独打开后续跑再另选一套审批。
7. 危险命令确认必须走到本 GUI 的 `confirm`。不得用 `bypassPermissions` 或 `--non-interactive-approval allow` 代替。

## 验收

- 界面只有「默认模式」「完全信任」，机器标识分别是 `bypass`、`autopilot`。
- 规范性句子不把 `partial-trust` 或 `full-trust` 写成机器标识。
- 一条不依赖 dsh 的会话能完成一次工具调用，结果符合当前锁定点的 `decideStepToolCall`。
- 该会话的权限策略只能是 `bypass` 或 `autopilot`，确认回调由本 GUI 提供。
- 九个插件没有被装回，也没有被改名迁移。

工具调用、危险命令确认、两档界面三项由本仓库 `apps/desktop/step-t4-verify.cjs` 核对。它驱动已组合扩展的 `tool_call`，不新开会话，也不另写一份不变量。

会话级验收由 `apps/desktop/step-t5-verify.cjs` 核对：一个本地假提供端把用户消息发出去、把模型回复取回来，断言回复落到旧契约形状、请求带的是 GUI 模型页里那把 key、模型配置经桥接落到 Step 存储根而下 CLI 自己的 `auth.json` 不动、改配置后下个回合用新 key、没配提供商时报错而不发请求、同一条会话复用历史而换会话不带别人历史、会话落在 Step 自己的存储根（OrchDesk 数据目录不落文件）、会话按绑定的工作目录取、权限值仍只有两档。投影规则本身由 `apps/desktop/step-model-bridge-verify.cjs` 逐条核对。危险命令确认的深度断言在 `step-session-verify.cjs`：它直接驱动会话的 `beforeToolCall`。

会话级验收已完成，属于 [PLAN](../80-路线图/计划.md) 的 T5。作曲栏发送的文本由锁定点的 `AgentSession` 执行（`apps/desktop/step-session.ts`），工具调用仍走锁定点裁决与两档预设，确认仍走本 GUI 弹窗。见 [PRD](../20-需求/运行时替换.md) 的「意图与已交付的结果」。

T5 的契约：作曲栏发送的文本由 Step 会话执行，不再经 `agent-turn.ts` 的 OpenAI 循环。会话的工具调用仍走锁定点裁决与两档预设，确认由本 GUI 提供。会话存储和模型凭证留在 Step 运行时自己的存储根（ADR 0005 第 5 条）。

### 模型配置的桥接

本 GUI 的模型页把提供商存在 OrchDesk 自己的 `userData/models.json`（key 用 safeStorage 加密），Step 会话认的是 Step 自己的 `auth.json` / `models.json`。两者格式不同，中间靠 `apps/desktop/step-model-bridge.ts` 投影（纯函数，不落盘）：

- 落点：`<Step 存储根>/gui/{models.json,auth.json}`。凭证仍在 Step 存储根内，但不碰用户在 step CLI 里配的 `<agentDir>/auth.json`。
- 形状：`providers` 是对象（Step 的形状，不是 GUI 的数组）；凭证只进 `auth.json`，`models.json` 里不得出现明文 key。锁定包用 schema 校验整份 `models.json`，`id` 的最小长度为 1；校验失败时不抛错，而是把整份配置静默换成空表。所以投影先丢掉空 id、首尾空白和没有地址的提供商——一个空 id 就会让所有提供商一起消失，表现仍是「No API key found」。选中的模型必须落在写出去的那份文件里，否则会话去读一个不存在的提供商。
- 映射：GUI 的 Ollama baseUrl 不带 `/v1`（GUI 走 `{base}/api/chat`），投影时补 `/v1`；`apiMode=responses` → `openai-responses`，其余 → `openai-completions`。
- 生效：会话缓存键含模型配置指纹（`configFingerprint`），用户改完设置页的下个回合就用新提供商/新 key，不会闷用缓存的旧凭证；只改无关提供商不打断对话。

没有可用提供商时回合直接报错，不发模型请求（不假装成功）。

GUI 会话只用 GUI 模型页的配置：会话拿到的是指向 `gui/` 的自建 `modelRuntime`，不会再回落去读 CLI 的 `models.json`。所以在只配过 step CLI、没在本 GUI 配过模型时，发送会得到「No API key found for the selected model」——这是有意为之（与改接前一致：那时用的也是本 GUI 的模型页），不是回退。
