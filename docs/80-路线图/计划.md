## T5 的边界

T5 已完成：`doSend` → `bridge.runAgentTurn` → `step-session.ts` → 锁定点的 `AgentSession`。

T5 必须遵守：不改 `decideStepToolCall`；不引入第二套审批；权限值仍只有 `bypass` 与 `autopilot`；界面仍只有两档文案；会话存储与模型凭据留在 Step 运行时自己的存储根（ADR 0005 第 5 条）。

T5 不因为「会话工厂存在」就自动完成。`createStepAgentSession` 与 `createStepCode` 本身不安装权限控制器，不能当作已接好的运行时；控制器随组合后的扩展进入会话（`bindExtensions`）。这条正是 T5 的验收依据：会话建起来不等于接好了。

## 不并行的原因

T2 和 T3 改的是同一进程、同一装载路径。拆给多个 Agent 会让一个 Agent 猜另一个 Agent 的接口。契约已经稳定，但写入范围重叠，所以串行。

## 评审

改接开始后，实现与评审分开。评审对照本 PLAN 的验证列和 [SPEC](../30-开发/替换契约.md)，不对照归档研究。评审轮次默认不超过 3。文档增量不派实现 Agent。T0 至 T5 与 M1 均已完成，运行时替换执行图闭合。
