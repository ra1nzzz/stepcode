# PLAN — 运行时替换

本页只排未完成的执行图。已完成的文档决定在 [CHECKPOINT](../00-项目/检查点.md)，不在这里写成正在做的工作。

- 日期：2026-09-30
- 契约：[SPEC](../30-开发/替换契约.md)
- 并行：no。写入范围都是桌面主进程的同一条装载路径

```text
T0 核对 Node
  └─ T1 证据点门禁
       └─ T2 卸下 dsh
            └─ T3 接上进程内组合
                 └─ T4 集成验证
```

T0 与 T1 都挡住 T2。T1 可以在证据点不变时跳过，但不能和 T2 同时改宿主。

## 不并行的原因

T2 和 T3 改的是同一进程、同一装载路径。拆给多个 Agent 会让一个 Agent 猜另一个 Agent 的接口。契约已经稳定，但写入范围重叠，所以串行。

## 评审

改接开始后，实现与评审分开。评审对照本 PLAN 的验证列和 [SPEC](../30-开发/替换契约.md)，不对照归档研究。评审轮次默认不超过 3。文档增量不派实现 Agent。T0 已通过，T1 已跳过，T2 已完成，T3 已完成。下一步是 T4，本页不开始 T4。
