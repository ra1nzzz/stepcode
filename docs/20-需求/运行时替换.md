# PRD — 替换运行时核

本页只回答意图和结果。实现接缝、输入输出和不变量在 [SPEC](../30-开发/替换契约.md)。为什么这样选在 [ADR](../70-决策/README.md)。

- 状态：意图已接受。执行图已完成。用户会话已接上 Step
- 日期：2026-09-30
- 规格级别：L3。只记录已经有证据的失败与回滚约束，不补写没有证据的性能预算或发布策略

## 为什么做

OrchDesk 的执行核是 dsh。要换成可跟随官方更新的 Step Code CLI，并沿用 CLI 已有模式，不新造一套执行策略。

## 谁使用

使用桌面宿主的人。人在界面上只看到两个权限档。机器标识不作为界面词。

## 解决什么问题

现有执行核不就是要跟随的官方 CLI。若把另一个同名仓库或宿主自己的授权档当成这次替换，产品身份和权限行为都会错。

## 成功标准

- 界面只有「默认模式」和「完全信任」。
- 完全信任不表示跳过危险命令确认。两档遇到危险命令都要确认。
- 一条不再依赖 dsh 的会话，其工具结果与锁定的 CLI 裁决一致，确认由本 GUI 完成。
- 九个旧插件的产品能力不计入这次成功。

行为细节和验收句子的权威页是 [SPEC](../30-开发/替换契约.md)。

## 明确不做什么

- 不引入「部分信任」。
- 不把完全信任做成跳过危险命令确认。
- 不把 STEPcode 的 EXPRESS 或 Part 21 能力做成产品功能。
- 不重新解释 OrchDesk 的轻模式、项目模式或模型协议 `chat`。
- 不把九个旧插件的能力算进这次替换的成果。

## 意图与已交付的结果

执行图已完成。已验证的是用户会话由锁定点会话执行，而不仅是已组合扩展的工具钩子。

用户发送路径已接入 Step 会话（`apps/desktop/step-session.ts`）。旧的 OpenAI 循环 `agent-turn.ts` 已删除，不留旁路；与它同时删除的两个套件（`agent-loop-verify.cjs`、`model-loop-verify.cjs`）只驱动旧循环。

第三个被删的套件 `session-merge-verify.cjs` 不只驱动旧循环：它的纯函数部分覆盖的 `session-merge.ts` 仍在 `persist-sessions` 生产路径上，该模块的自动化覆盖随删除归零。已把纯函数部分作为独立套件恢复（`session-merge-verify.cjs`，8 项），原套件里驱动旧循环的 IPC 部分不恢复。

本 GUI 模型页配的提供商现在真的到达回合：`step-model-bridge.ts` 把 GUI 自己的 `models.json` 形状投影成 Step 原生的 `auth.json` / `models.json`，写到 `<Step 存储根>/gui/`，不碰用户在 step CLI 里配的凭据。之前这一环从未接上——模型页写的是 OrchDesk 的 `userData/models.json`，而会话读的是 Step 自己的根，用户在设置页配完再发送会得到「No API key found」。落点选择、格式与映射见 [替换契约](../30-开发/替换契约.md)。
