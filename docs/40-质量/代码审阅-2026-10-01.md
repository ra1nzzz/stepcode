## 第九轮（同日，发布路径不再被软链绕过）

`publishSkill` 的白名单用 `path.resolve` 判前缀，而 **`resolve` 不解析符号链接**：`skills/evil.skill` 只要是指向 `~/.ssh/id_rsa`（或任何本机文件）的软链，前缀检查照样通过，随后的 `readFileSync` 跟着链接读出去——把任意文件上传到技能市场。它同时还有个不一致：校验的是 `resolved`，读的却是入参原路径。

### 密钥进输出的通道与子进程 env 的交叉复核（第十五轮，测量补盲）

BUG-049 修完子进程 env 之后，顺着同一族问题量了两件事：**密钥值会不会被写进日志/输出**，以及**这次剥离会不会打断运行时自己的目录发现**。

- **产品代码里没有任何密钥值被插进输出**。扫描覆盖 `apps/desktop` 的 `*.ts` + `*.cjs`（排除 `node_modules/dist/release/vendor`），
  判据是「同一行既有输出动词（`log` / `console.*` / `process.stdout` / `write` / `toast` / `recordSandbox` / `append`）
  又有密钥名（apiKey / api_key / token / secret / password / cipher / credential），且以模板插值或字符串拼接的形式出现」。
  结果：候选点 0。
- **这条 0 是带正控的 0。** 我第一次用 `grep` 的 BRE 写同样判据时，字符类里想放方括号写成 `[a-zA-Z0-9_.\[\]]`，
  BRE 把第一个 `]` 当成类的结束，于是**植入的样本 `key=${p.apiKey}` 也没匹配上**——那个「仓库里 0 命中」是扫描器坏了，不是代码干净。
  改用 node 重写判据，并在脚本里内置三条正控（模板插值、字符串拼接、变量名后缀形态），控制不匹配就退出码 2 拒绝出结论；
  三条控制全过后才得到上面那个 0。这条教训与本页「扫描器命中后先手工复现、并跑一份已知正确的样本」是同一条规矩的第二次应用。
- **`sandbox-log.json` 的记录面**：`recordSandbox` 只落 `tool / kind / target / decision / reason / mode / ts`；
  `reason` 由调用方构造，上面那条扫描同样覆盖了它，没有密钥进 `reason` 的路径。
- **剥离不影响运行时自己**：`CHILD_ENV_STRIP` 只作用于**复制给子进程的 env 副本**（终端与 MCP server），
  不改 `process.env` 本体；本壳自己的目录解析走 `data-dir.ts:569-571` 的注入解析器优先，
  Step 运行时是进程内嵌入（`createStepExtensionInline`，宿主侧传 `env: {}`，不 spawn），
  所以 `ORCHDESK_HOME` / `ORCHDESK_DATA_DIR` / `ORCHDESK_STEP_RUNTIME` 被剥掉不会打断任何合法路径。
  反证已由 BUG-049 的判据承担：`buildChildEnv` 保留普通变量、`config.env` 显式赋值仍能覆盖。

**本轮结论**：密钥不出现在任何输出通道；子进程 env 只带子进程该带的东西；两条都是量出来的，判据脚本自带正控。

两条如实记在这：

1. **stdin 监听未被证明。** 删掉两处 `child.stdin.on('error')` 后用例仍绿：Windows 上向已关闭的管道读端写入得到的是静默 EOF，而不是 POSIX 那样的 EPIPE `'error'` 事件，本机构造不出可观测的异步 error。监听器按 Node 语义与 `terminal-pty.ts:321` 已经写下的同一条规矩保留，属防御性修复。要判红得能在客户端内部替换 `spawn`；`dist/mcp-client.js` 是 ESM 静态 import，本机没有可用的 mock 缝。用例名已改成它实际断言的内容，不再自称反证
2. **`encryptKey` 返回空串那条守卫今天到不了。** `credentials.encryptSecret` 是纯 node:crypto 的 AES-256-GCM，除空输入外不会返回空串，所以 `models-save` 里的「key 落不下就报失败」在当前平台是死分支。它挡的是「将来主密钥来源换成 safeStorage 或平台 keystore 后静默丢 key」，与 `PRD NFR` 的「凭据必须加密」一致。没有为它编造用例

变异前后实测：`credentials-verify.cjs` 45 通过 0 失败（原 40）；`mcp-client-verify.cjs` 12 通过 0 失败（原 10）。数字为本轮实跑。
