# YTPX 审阅（2026-10-01）

按 [YTPX Skill v1.1](YTPX/YTPX-Skill-v1.1/SKILL.md) 的五维评分审 `apps/desktop/renderer`。技能包解在 [YTPX/](YTPX/YTPX-Skill-v1.1/)，未改运行时技能目录，也未改界面代码。

评分依据是 [YTPX-SCORE-SPEC](YTPX/YTPX-Skill-v1.1/SPEC/YTPX-SCORE-SPEC.md)。该规范只给维度和分值，没有给每一分的判据，所以本页的打分是对照规范条目的判断，不是规范自带的量表。

## 总分

**54 / 100。** 未达到规范对标的 Linear、Raycast、Claude 那一档。差距最大的两项是原创性和 Agent 体验：界面能用，但拿掉名字看不出是谁，回合进行中的状态要打开右栏才看得见。

| 维度 | 分值 | 得分 | 判断 |
|---|---|---|---|
| Visual Craft | 25 | 14 | 尺度立住了，原创性没有 |
| Cognitive UX | 20 | 13 | 第一眼能懂，信息架构仍是功能清单 |
| Interaction Quality | 20 | 12 | 反馈在，但主路径上的状态不够重 |
| Agent Experience | 20 | 8 | 权限和确认有，意图解释和记忆没有 |
| Emotional Resonance | 15 | 7 | 有一句自己的话，没有品牌感 |

## Visual Craft 14/25

- Layout 3/5。四列网格清楚，主会话有 760px 栏宽。窄窗已改成抽屉，不再硬裁。
- White Space 2/3。间距收成 4、8、12、16、24。设置页组间 24px，组内仍偏紧。
- Visual Hierarchy 3/5。页面标题 20px，正文 13px，有一跳。欢迎页那句文案升到了 15px 副题。
- Color System 2/3。暖灰与角色色分开了，动作蓝仍是通用蓝。
- Motion Design 2/4。有入场、有减弱动效。脉冲只剩「正在跑」。没有状态切换的专属过渡。
- Micro Interaction 2/3。焦点环在，行内操作默认可见。浮动按钮的说明在键盘聚焦时出现。
- Responsive 2/2。700px 以下抽屉，560px 以下欢迎页顶对齐。
- Originality 0/5。配色换了，但仍是通用深色工作台。规范把原创性单独列成 5 分，这一项没有得分。

字号尺度与规范的 [typography.token.json](YTPX/YTPX-Skill-v1.1/TOKENS/typography.token.json) 不一致：规范正文 16px、标题 32px，本界面正文 13px、标题 20px。这是桌面工作台的密度选择，不是漏改。若要按规范对齐，会把现在的密度打散，本页不建议直接套用。

## Cognitive UX 13/20

- First Understanding 4/5。欢迎页一句「从一句话开始。不会替你编任务。」，第一眼知道这里做什么。
- Information Architecture 3/5。导航是会话、插件、设置，按功能分，不是按用户目标分。规范的 [WORKSPACE-SPEC](YTPX/YTPX-Skill-v1.1/SPEC/WORKSPACE-SPEC.md) 要求导航代表目标。
- Efficiency 3/5。发送、停止、切换会话都在主路径上。设置页仍是长页，找一项要滚。
- Error Prevention 3/5。不可逆操作有二次确认，模型没配时回合报错而不是假装成功。

## Interaction Quality 12/20

- State Feedback 3/5。右栏有「这一回合正在进行」。主区只靠头像脉冲，状态不够重。
- Consistency 4/5。字号、圆角、间距已收成尺度。内联样式还在，设置页仍有手写间距。
- Control 3/5。进行中可以停止。停止之后没有「已停止，可以重试」的明确落点。
- Interaction Pleasure 2/5。过渡短、不打扰。没有一处让人觉得是为这个产品设计的。

## Agent Experience 8/20

对照 [agent.rules.yaml](YTPX/YTPX-Skill-v1.1/RULES/agent.rules.yaml) 的五条硬要求：

| 规则 | 现状 | 判断 |
|---|---|---|
| require_state | 右栏有状态行，主区没有 | 部分满足 |
| require_progress | 步骤点在右栏，默认右栏关闭 | 不满足 |
| require_explainability | 工具行有名字，没有「为什么做这一步」 | 不满足 |
| require_permission_control | 两档权限，危险命令走确认弹窗 | 满足 |
| high_risk_action_confirmation | 同一审批入口 | 满足 |

- Intent Understanding 1/5。发送后直接进回合，没有复述理解。
- Trust Interface 3/5。权限档和确认在，这是五条里唯二满足的。
- Human-Agent Collaboration 2/5。可以停止，不能改写进行中的一步。
- Memory Experience 2/5。会话历史在，没有「我记得你上次做什么」的界面表达。

## Emotional Resonance 7/15

- Brand Feeling 2/5。只有那一句文案是自己的。颜色、logo 渐变、布局都是通用的。
- Delight Moment 2/5。没有一处专门的完成瞬间。回合结束是状态行换字。
- Premium Quality 3/5。对比度、焦点环、尺度做过功课，耐看，但不高级。

## 不在本页

- 不改界面。本页是审阅。
- 不把规范的 16px 正文直接套进桌面壳。密度是这个产品的选择，要改先改计划，不在审阅里改。
- 规范的 [screenshot-review-prompt.md](YTPX/YTPX-Skill-v1.1/REVIEW/screenshot-review-prompt.md) 要求截图审阅。本页没有截图，判断来自样式表和渲染路径。

## 2026-10-01 执行

按本页「如果要继续」的前两项落地，没有再换一轮颜色。

- 主区回合条：会话页消息列表上方增加一行 `role="status"`，显示「正在进行 / 等待确认」、当前步骤名和 `done/total`。数据与右栏同源，右栏关闭时主区仍能看见状态、进度和原因。
- 视觉结论：logo 去掉紫蓝渐变，只用决策者暖铜 `--ceo-solid`。这是这套界面里唯一不属于通用组件库的颜色，拿掉名字后仍能靠这一处认出来。
- 产品名：用户可见的名称改为 StepCode Desktop。窗口标题、导航名、状态栏、消息署名、开机启动文案、关于页都改了。`window.OrchDeskFork` 这类代码标识符和数据目录路径没有改，改了会断。

## 如果要继续

按得分最低的两项排，不按视觉吸引力排：

1. Agent 状态进主区。回合进行中时，主区要有一行可读的状态和进度，不依赖右栏打开。
2. 原创性。先定一个只属于这个产品的视觉结论，再谈换色。现在换色已经做了，再换一轮不会加分。
