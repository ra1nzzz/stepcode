# ADR 0004 — GUI 只保留两档权限

- 状态：已接受
- 日期：2026-09-29
- 取代：[ADR 0003](0003-采用-step-code-预设.md) 第 2、3 条中关于界面用词和四档全暴露的部分。运行时来源与锁定点仍以 ADR 0003 为准。

## 背景

CLI 有 `ask`、`read-only`、`bypass`、`autopilot` 四档。用户要求本 GUI 只保留后两档，名称分别为「默认模式」和「完全信任」。

这不是新的执行策略。两档的工具裁决仍是锁定点里对应预设的 `decideStepToolCall`。

## 决策

| 规范词 | 机器标识 | 对应的 CLI 预设 | 本 GUI |
|---|---|---|---|
| 默认模式 | `bypass` | `bypass` | 提供，且是未单独选择时的产品默认 |
| 完全信任 | `autopilot` | `autopilot` | 提供 |

1. 本 GUI 不提供 `ask`、`read-only` 的入口，也不把它们显示成上述两个名称。
2. 机器标识保持 `bypass`、`autopilot`。不用 `default`，也不新造 `full-trust`。`default` 已是宿主兼容词和 OrchDesk 授权档，不能再占用。
3. 「完全信任」只表示选用 `autopilot`。它不表示跳过危险命令确认。两档对危险命令的确认行为相同；差别是 `autopilot` 会在瞬时模型失败后续跑。
4. 「部分信任」仍然撤回。它不是这两档的任何一个。
5. 若运行时带回 `ask` 或 `read-only`，界面不得把它标成默认模式或完全信任。下一次由本 GUI 发出的预设只能是 `bypass` 或 `autopilot`。

## 后果

界面、提示、通知和 API 人读文案只用「默认模式」「完全信任」。日志和配置保留机器标识。用词表见 [术语](../00-项目/术语.md)。增加第三档或改这两档的 CLI 行为，需要新的 ADR。
