# ADR 0005 — 进程内组合运行时核，插件随 dsh 删除

- 状态：已接受
- 日期：2026-09-29
- 取代：[ADR 0003](0003-采用-step-code-预设.md) 的「未决」。不改锁定点，不改 [ADR 0004](0004-gui-两档.md) 的两档。
- 核对记录：[嵌入与插件](../99-归档/研究/2026-09-29-嵌入与插件.md)

## 背景

用户确认公开仓库名为 `ra1nzzz/stepcode`，并要求先分析库嵌入与子进程、以及哪些 OrchDesk 插件随 dsh 删除，再写入文档。

## 决策

1. 公开远程名称是 `ra1nzzz/stepcode`。作此决定时该仓库仍不存在。本 ADR 当时不创建它，也不推送。
2. Agent 运行时核在进程内组合，不以后台子进程作为产品边界。
3. 组合接缝与官方 CLI 相同：把权限策略传给 `createStepExtensionInline`，由本 GUI 提供 `confirm`。角色对应 `apps/cli/src/ui/runtime/approval.ts` 的 `createApprovalProvider`。策略只能是 `bypass` 或 `autopilot`。
4. 不单独把 `createStepCode` 或 `createStepAgentSession` 当作已接好的运行时。二者不安装权限控制器。
5. 会话存储和模型凭据留在 Step 运行时自己的存储根。本 GUI 不另造会话格式。
6. 不迁移 OrchDesk 的 `sandboxPolicy`。不向 Step host 发送 `sandbox.enabled`。工具边界是锁定点的 `decideStepToolCall`。
7. `apps/desktop/dsh-runtime.ts` 装载的 9 个 Cordis 插件全部随该运行时删除。能力不迁入这次替换。市场插件装载器同样删除；不逐个迁移市场目录。
8. 宿主服务 `sandboxPolicy`、`approval`、`agents` 随 dsh 停止。桌面桥在改接时移除或显式返回不可用，不改接到 Step Code 的内部对象上。
9. 本 ADR 不修改 OrchDesk 仓库。清单已经写完，改接是后续增量。

## 被否定的方案

- **子进程 `--sdk-stdio`，并用其 `permissionMode` 表示两档**：该集合是 `default`、`acceptEdits`、`plan`、`bypassPermissions`、`dontAsk`。`bypassPermissions` 跳过 SDK 审批回调。这不是 `bypass`，也不是 `autopilot`。映射成完全信任会跳过确认。
- **子进程 `--mode rpc`**：命令集不能设置 `bypass` 或 `autopilot`。`extension_ui_request` 的 `confirm` 没有核对到与 `decideStepToolCall` 相连。
- **只传 `--approval-mode auto`**：这只选中底层 `auto`。要折成 `autopilot` 还要 `STEP_AUTOPILOT`，并且非交互审批不能是 `deny`。即便这对启动参数折对了预设，没有 `ui.confirm` 时危险命令仍被拒绝，不是交给本 GUI 确认。
- **用 `--non-interactive-approval allow` 表示完全信任**：那只放行普通确认。危险命令在没有界面时仍然失败关闭。它不是 `autopilot`，也不是确认对话框。
- **为 `prompt` 插件保留 Cordis**：它不注入 dsh-agent，但只由 dsh 装载器装载。保留 Cordis 等于留下要替换的运行时。
- **把 OrchDesk 的 `default` / `trusted` / `paranoid` 改名成两档**：ADR 0004 已经禁止。authz 插件随 dsh 删除，不改名迁移。

## 后果

实现前必须满足 `@step-harness/coding-agent` 的 `engines.node >=22.19.0`。Electron 36 自带 Node 是否满足，本 ADR 没有核对。不满足时先升壳的运行时。不得因此改用 `--sdk-stdio` 的权限词。

工具执行与 Electron 主进程同崩。这是接受的代价。以后若要改成子进程，新 ADR 必须证明三件事：子进程仍走 `decideStepToolCall`；GUI 能分别设置 `bypass` 和 `autopilot`；危险命令确认不经过 `bypassPermissions` 或 `--non-interactive-approval allow`。

跟随官方更新仍是移动锁定点并记 ADR。`step update` 不移动这个锁定点。

九个插件的产品能力（意图门、上报、授权白名单、专家团、四域记忆、提示词库、补偿层、自进化）不在这次替换的验收里。要恢复其中任何一项，另记 ADR，不能在改接时顺手接回。

## 后续

决策第 1 条只表示本 ADR 当时不创建远程。2026-09-29 的建仓增量已创建公开仓库 https://github.com/ra1nzzz/stepcode 。创建记录见 [公开仓库检查点](../99-归档/检查点/2026-09-29-公开仓库.md)。本 ADR 的嵌入方式和插件处置不变。
