# ADR 0007 — 精简版桌面壳归属 stepcode，orchdesk 恢复 dsh 运行时

- 状态：已接受
- 日期：2026-09-30
- 取代：无。不改 [ADR 0003](0003-采用-step-code-预设.md)、[ADR 0004](0004-gui-两档.md)、[ADR 0005](0005-进程内嵌入与插件删除.md) 的决定内容，只改承载仓库。
- 相关：ADR 0005 第 9 条当时写「本 ADR 不修改 OrchDesk 仓库」。本 ADR 是对该条的修正。

## 背景

Step Code CLI 的进程内接缝（`createStepExtensionInline` + 本 GUI 的 `confirm`）已经完成并把九个 Cordis 插件从 OrchDesk 卸下。但承载它的仓库错了：OrchDesk 是本地优先的多 Agent 编排工作台，底座是 dsh / Cordis。把它的 dsh runtime 卸掉，等于把 OrchDesk 这个产品改成另一个东西。

用户随后明确：本仓库（`ra1nzzz/stepcode`）吸纳 OrchDesk 的精简版并作为 stepcode GUI；OrchDesk 本身保持 dsh runtime 不变。

此前已经把 4 个提交推上了 `ra1nzzz/orchdesk` 的 main（T2 卸下、T3 接缝、T4 验证、review 修复）。这不是计划内的改动，是需要纠正的错误。

## 决策

1. `ra1nzzz/orchdesk` 的 main 回滚到 `e29881bb6d2ab751549fc2d3f335a5339e747a83`，即第一次改动前的 HEAD，用 force push 重写远端。它有完整可用的 dsh runtime 和九个插件。回滚前已核对：没有任何 tag 指向被丢弃的 4 个提交。
2. 精简版桌面壳进 `ra1nzzz/stepcode`，位置 `apps/desktop`。内容取自被回滚掉的那次工作的文件树（本地对象库里仍在，commit `ec61e6b`），不是从 orchdesk 另抄一份。
3. 精简版只带桌面壳与它自己的工作区脚本。不搬 `packages/plugin/*`（九个插件）、`packages/bundle/desktop`（Cordis patch）、`references/deepseek-harness`。dsh 在这份代码里已不装载，不需要它们。
4. orchdesk 的工作区 globs 不再适用于 stepcode。本仓库的 `pnpm-workspace.yaml` 只声明 `apps/*`。
5. `@deepseek-ai/cordis` 的类型引用改为本地最小形状。精简版里那个 `apply(ctx)` 什么都不调用，赎回公网依赖。
6. 锁定点 `93ebc5bea25032a77af007a968a8998b492989f5` 与 Electron `36.9.5` / Node `22.19.0` 不变。证据点 `b68a955766dffd5fe45e3e0e2ca075d2b297ee65` 不前移——它是 orchdesk 的证据点，现在属于另一个仓库的历史。

## 被否定的方案

- **在 orchdesk 上继续，另开一个 stepcode GUI 仓库**：会把同一个 Electron 壳复制成两份。用户已明确本仓库是精简版的归宿。
- **在 orchdesk 上加 revert 提交而不是 force push**：main 上会留下 4 个「先卸下 dsh 又装回去」的提交。对本地优先的工作台来说，那段历史比没有更糟。
- **把 orchdesk 的九个插件也搬进 stepcode**：ADR 0005 已删且不迁移。搬回来等于推翻那条决定，而精简版并不装载它们。
- **用 git subtree / submodule 引用 orchdesk**：会把一个不再需要的 dsh 依赖树拉进本仓库，编译和验证都要为它付出成本。

## 后果

- `ra1nzzz/orchdesk` 的 main 不再是 dsh 的完整实现镜像，而是回到 `e29881b`。任何想在精简版上继续的人要用 stepcode 仓库。
- 本仓库从此既是知识库也是代码仓库。`docs/` 保持五件套控制面，`apps/desktop` 是产品代码。两层不混：文档不写实现细节，代码注释不复制规格。
- 证据点 `b68a955` 现在是历史提交，不随本仓库演进。之前「证据点不前移」的约束转化为「不回滚 orchdesk 之后的状态」。
- 精简版桌面壳的 `verify` 链原来指向 orchdesk 根的 `scripts/`，现在由本仓库自己的 `scripts/` 满足。`tsconfig.base.json` 同样搬入。
- `step-extension.ts` 的锁定点解析从 `__dirname` 向上找 6 层。`D:\Code\stepcode\apps\desktop` 与 `D:\Code\orchdesk\apps\desktop` 深度相同，仍能找到 `D:\Code\Step-Code-93ebc5be`。也可用 `ORCHDESK_STEP_CODE` 显式指定。

## 后续

精简版搬入后重跑：桌面 `tsc`、`step-extension-verify.cjs` 12 通过、`step-t4-verify.cjs`、`step-session-verify.cjs`、`dsh-runtime-verify.cjs` 5 通过、`arch-guard-verify.cjs` 28 通过。详见 [检查点](../00-项目/检查点.md)。

用户发送路径仍未接入 Step 会话，仍走 `agent-turn.ts` 的 OpenAI 循环。那是本仓库唯一剩下的产品缺口，见 [计划](../80-路线图/计划.md)。
